# 产品需求文档（PRD）

版本：0.3（评审修订稿）  
产品：WebPilot，开源技术选型调研助手

## 1. 背景与目标

开发者对比开源项目时，通常要搜索官网、仓库和文档，手动整理许可证、部署方式及功能。WebPilot 将公开资料调研组织为可观察的任务，并以来源可追溯的报告呈现结果。

首版目标：针对中文或英文的开源技术选型问题，完成「创建任务 → 搜索 → 抓取和提取 → 证据检查 → 生成报告 → 查看来源」闭环，失败时保留过程和原因。

非目标：保证所有事实真实；自动登录网站；绕过验证码、访问限制或付费墙；自动购买、提交表单、修改远端数据；通用电脑操作；企业级多租户。

## 2. 用户与典型场景

- 目标用户：需要比较开发工具的个人开发者；团队协作不在首版范围。
- 示例任务：“比较 Qdrant、Milvus、Weaviate 的开源许可证、部署方式和主要功能，给出来源。”
- 输入：调研问题，最多 2000 字；候选项目名直接写在问题中，可选最大来源数（1–20，默认 10）。
- 输出：Markdown 报告、引用的证据和来源链接、任务过程与错误信息。
- 默认只读公开页面；用户需自行核对重要结论，报告明确区分有证据的结论和信息不足。

## 3. 功能需求及验收

| ID | 优先级 | 功能 | 验收标准 |
|---|---|---|---|
| FR-01 | P0 | 创建任务 | 提交合法问题后返回任务 ID 和 queued 状态；空问题和越界参数返回可读错误。 |
| FR-02 | P0 | 任务规划 | 模型生成结构化子问题和检索词，计划及其版本可查看；步骤数量有上限。 |
| FR-03 | P0 | 搜索与采集 | 搜索适配器返回标题、URL、摘要；去重后抓取公开网页；动态页面按配置使用浏览器回退；失败不终止其他来源。 |
| FR-04 | P0 | 来源与证据 | 保存 URL、标题、采集时间、原文片段及其 ID；报告引用关联到有效证据，来源可从界面打开。 |
| FR-05 | P0 | 证据检查和报告 | 按问题检查证据覆盖；有限次数补充检索；不足时明确标记未知。报告包括问题、比较、结论、局限和引用。 |
| FR-06 | P0 | 查看过程 | 任务详情展示状态、步骤事件、来源与报告；事件可通过 SSE 推送，刷新后仍可查询。 |
| FR-07 | P0 | 取消与恢复 | 排队或运行中的任务可取消；失败、中断或取消后在次数和兼容性条件满足时可手动恢复。已完成步骤和证据保留，恢复不得触发非只读操作。 |
| FR-08 | P0 | 失败反馈 | 配置缺失、搜索/模型失败、无有效证据、超限均返回或记录明确原因，不把失败伪装为成功报告。 |
| FR-09 | P0 | 导出 | 已生成报告可下载为 UTF-8 Markdown，包含来源 URL。 |
| FR-10 | P1 | 用户上传文档 | 支持 PDF、Markdown 文档，标记来源与页码；单独设计解析和大小限制。 |
| FR-11 | P1 | 人工接管 | 登录或高风险操作前暂停，确认或拒绝后继续；首版不执行这些操作。 |
| FR-12 | P1 | 可配置模型与成本看板 | 界面选择已配置的模型，展示实际可获得的 token、费用与耗时；缺失数据标为未知。 |

## 4. 页面与交互

1. **任务列表/新建**：输入问题与来源上限，查看历史任务、状态、创建时间。
2. **任务详情**：阶段状态、事件时间线、来源列表、进度与取消/恢复操作；刷新后通过接口恢复视图。
3. **报告**：Markdown 正文、引用编号、证据片段和原始链接；展示“证据不足”和采集时间。

首版采用桌面优先的响应式布局；基础键盘操作、语义标签与可见焦点为必需。图表不是首版必需。

## 5. 非功能需求与约束

- 单机单用户；服务仅绑定本机地址，不提供公开互联网部署方案。
- 调研与模型服务均可能收费或超时；页面展示配置和运行错误，不预设成本或成功率。
- 给每次任务设置步骤、来源数、运行时间、单次页面大小上限；具体默认值见架构文档。
- 搜索结果和页面内容均为不可信输入：不能把网页内容当作系统指令，也不能赋予网页发起工具调用的权限。
- 仅访问公网 HTTP(S)，网络出口检查、重定向和 DNS 解析规则见架构文档；不声称模型层提示词能完全防御注入。
- 日志不记录 API Key；浏览器使用独立临时配置，不接入用户日常浏览器或登录态。

## 6. 首版完成定义

在配置可用模型与搜索服务的环境中，能通过界面提交任务、观察过程、查看包含真实证据引用的报告、导出报告；失败和取消可见，符合恢复条件时可恢复。使用固定测试数据和可控假服务验证核心流程，并至少完成一次真实服务端到端验证，记录限制和成本。

## 7. 结果质量与能力边界

- `completed` 表示报告已生成并通过结构检查，不等于任务问题被完整解决。报告必须带 `quality=complete|partial`，前者要求规划中的全部子问题均有支持证据且无未解决冲突；后者列出缺失项、冲突和失败来源。这是系统判定，仍需人工评测。
- 没有任何子问题得到有效证据支持时为 `failed/NO_EVIDENCE`，不生成正式报告。部分证据足够支撑至少一个子问题时，可以生成 partial 报告；硬运行预算耗尽且报告尚未原子提交时为 `failed/LIMIT_REACHED`。
- 首版的浏览器回退用于渲染公开动态网页、读取和截图，不支持点击、填表、登录及通用交互操作。浏览器禁用时界面明确展示“仅 HTTP 采集”，不得宣称已交付完整浏览器 Agent。
- 核心模型调用次数、token 用量（如可获取）、外部调用耗时和错误计数在 P0 就记录；成本看板及界面选模型仍为 P1。未知费用不展示为零。
- 任务进度展示当前阶段与已处理来源数，不根据模型估计伪造完成百分比。
