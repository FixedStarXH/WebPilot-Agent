# WebPilot 前端页面设计（评审稿）

本稿依据 [产品需求](./requirements.md)、[HTTP API](./api.md) 和 [Agent 协议](./agent-contracts.md) 设计。目标用户是需要快速比较开源技术的开发者。前端框架尚未确定；本稿定义页面、状态和视觉规则，不表示界面已经实现。

## 1. 产品定位与视觉方向

**定位：调研工作台。** 视觉重点是让用户看清“任务正在做什么、结论依据是什么、哪里仍不确定”。目前提供三套可选模板：[A 深色调研控制台](./frontend-preview.html?theme=console)、[B 文献式调研桌面](./frontend-preview.html?theme=editorial)、[C 实时任务指挥台](./frontend-preview.html?theme=signal)；可以从[对比页](./frontend-options.html)打开。下方颜色 token 和布局细节以 A 为基线，选定方向后再更新为最终设计系统。

参考的设计指导来自本地 `ui-ux-pro-max` skill：任务过程要有阶段反馈，异步更新提供一处有意义的状态播报，表单错误就近展示并可通过键盘定位；深色界面需满足文字对比度和可见焦点。该 skill 的自动整体布局建议偏 FAQ，未采用其 FAQ 导航结构。

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0F172A` | 页面背景 |
| `--surface` | `#1B2336` | 主面板 |
| `--surface-raised` | `#263248` | 悬浮层与选中项 |
| `--text` | `#F8FAFC` | 主文字 |
| `--text-muted` | `#B8C5D6` | 辅助说明，实际实现需测对比度 |
| `--border` | `#475569` | 分割线与边框 |
| `--accent` | `#22C55E` | 主要按钮与成功 |
| `--warning` | `#FBBF24` | partial、缺失与冲突 |
| `--danger` | `#F87171` | 失败与不可恢复错误 |
| `--focus` | `#FFFFFF` | 键盘焦点轮廓 |

中文正文使用系统可用的清晰无衬线字体；英文和数字优先 IBM Plex Sans，任务 ID、时间和代码片段使用 JetBrains Mono。正文 16px、行高约 1.6；报告正文最大宽度约 76ch，长 URL 允许换行。外部字体加载失败时使用本地回退，不影响阅读。

## 2. 信息架构与页面

```text
/tasks                 任务列表 + 新建任务
/tasks/{task_id}       任务详情：过程 / 报告 / 来源 三个页内视图
/tasks/{task_id}?tab=report  可直接分享的报告深链接（仅本机）
```

**任务列表与新建（首页）**

- 顶部：项目名、当前能力状态（“HTTP 采集”或“Edge 动态网页已启用”）、配置状态。不显示或回显 API Key。
- 主区左侧：问题输入框、来源上限（默认 10）、“开始调研”按钮；输入示例围绕开源项目选型。主操作提交后立即显示排队状态并跳转任务详情。
- 主区右侧：历史任务列表。每项展示问题摘要、状态、创建时间和可点击详情；状态文字与颜色同时表达含义，不只靠颜色。
- 配置未就绪时按钮禁用，并给出“请在本地 `.env` 配置 DeepSeek/Tavily Key”的明确说明；页面仍可查看历史任务。此前已创建的排队任务不因前端刷新而丢失。

**任务详情：过程**

- 顶部固定任务标题、状态、attempt、当前阶段、取消/恢复操作。只在运行或排队时显示取消；只在失败/取消且可恢复时显示恢复。取消请求已提交但仍在运行时显示“正在停止”，禁止连续点击。
- 左列为阶段时间线：规划、搜索、采集、证据检查、报告。列出实际事件时间与结果，失败步骤可展开错误原因；不显示伪造百分比。
- 右列为来源进度与最近事件。来源只显示已尝试数和上限、成功/失败数；失败来源保留原因。SSE 更新合并到一处 `role=status` 文案，避免屏幕阅读器不断重复整条时间线。
- 刷新时先请求任务和事件历史，再订阅 SSE；按 sequence 去重。网络断开显示“连接中断，正在重连”；任务仍可通过普通 HTTP 查询。

**任务详情：报告**

- 阅读区顶部：`完整` 或 `部分结果` 标签、生成时间、Markdown 下载按钮。partial 时先显示未覆盖维度和冲突提示，再展示结论；失败或尚未生成时用明确的空状态替代空白报告。
- 每个结论的证据引用渲染为 `[1]` 等可点击编号。点击后右侧“证据检查栏”显示原文片段、页面标题、采集时间和“打开来源”链接。鼠标和键盘均可打开；关闭后焦点返回引用。
- 报告正文仅渲染受限 Markdown：禁用原生 HTML、外部图片和脚本；来源 URL 必须由后端 source 记录生成并限制为 HTTP(S)。

**任务详情：来源**

- 来源列表按成功、失败和跳过区分，并显示标题、域名、最终 URL、采集时间、截断标记和证据数量。
- 展开某来源可检查保存的证据片段及关联的子问题；搜索摘要不标成正式证据。失败来源展示可读原因。
- 来源链接始终在新标签页打开，配有外站提示。

## 3. 桌面与移动布局

桌面宽度 ≥1024px：左侧窄导航、中央主内容、右侧可收起的证据栏。阅读区应始终优先，右栏不遮挡报告。768–1023px：导航缩为顶部，证据栏改为抽屉。≤767px：单列，任务表单在列表之前；过程与来源为卡片；证据栏使用全屏抽屉。最窄按 375px 检查，不产生横向滚动。

主要操作按钮点击目标至少 44×44px；按钮之间至少 8px。长任务名最多显示两行，完整内容在详情页可读。所有标签和抽屉可用键盘操作，支持 Esc 关闭抽屉并恢复焦点。

## 4. 交互与异常状态

| 状态 | 用户看到的内容 | 可执行操作 |
|---|---|---|
| `queued` | 已排队，等待 worker；不显示假进度 | 取消 |
| `running` | 当前阶段、真实步骤与来源进度 | 取消、查看历史 |
| `running + cancel_requested` | 正在停止，说明外部调用结束后生效 | 查看历史 |
| `completed + complete` | 完整报告、证据入口、下载 | 查看报告/来源 |
| `completed + partial` | 部分结果和明确的缺失项 | 查看报告/来源、下载 |
| `failed` | 错误原因和已保存的过程；若可恢复显示恢复入口 | 恢复或新建任务 |
| `cancelled` | 已停止及已处理来源数 | 恢复或新建任务 |
| 配置缺失 | 缺少哪个服务的配置，不展示密钥值 | 查看旧任务；到本地配置 |
| SSE 中断 | 重连提示，保留已有数据 | 手动刷新状态 |

表单输入限制在客户端就近提示，服务端 422 也落回具体字段；提交失败时顶部错误摘要聚焦，并保留用户输入。恢复返回 `RESUME_INCOMPATIBLE` 或次数耗尽时，解释原因并提供“复制原问题新建任务”，不显示无效的重试按钮。页面只在有真实报告时显示下载入口。

## 5. 接口映射与实施边界

| 页面功能 | API |
|---|---|
| 创建与列表 | `POST /tasks`、`GET /tasks`、`GET /capabilities` |
| 任务状态和过程 | `GET /tasks/{id}`、`GET /tasks/{id}/steps`、`GET /tasks/{id}/events`、`GET /tasks/{id}/events/stream` |
| 取消与恢复 | `POST /tasks/{id}/cancel`、`POST /tasks/{id}/resume` |
| 来源与证据 | `GET /tasks/{id}/sources`、`GET /tasks/{id}/evidence` |
| 报告与导出 | `GET /tasks/{id}/report`、`GET /tasks/{id}/report/download` |

所有路径以 `/api/v1` 为前缀。创建和恢复生成 `Idempotency-Key`；同一次网络重试复用该值。当前仓库的任务基础模块只实现了其中一部分 API，前端正式开发需与后续接口模块同步完成。界面不得把尚未接入的 DeepSeek、Tavily 或 Edge 显示为“已就绪”。

## 6. 前端验收

1. 375、768、1024、1440px 下检查排版，报告和来源无横向溢出。
2. 键盘完成新建、切换视图、打开引用、关闭证据栏、取消和恢复；焦点位置可预测。
3. 检查正文/辅助文字对比度、可见焦点和 `prefers-reduced-motion`。
4. 模拟空列表、配置缺失、排队、运行、partial、失败、取消、SSE 断线与重连。
5. 引用的证据 ID、来源 URL 和报告显示一致；不渲染来自网页的 HTML/脚本。

前端实现建议采用 Vue 3 + TypeScript + Vite（适合独立 FastAPI API 项目，开发部署简单），这是建议而非已批准的技术约束；最终选择前检查现有代码和开发环境。
